# Grok Bot 头像栏目额度读取设计

日期：2026-11-09  
目标版本：搞词元 4.12（构建 13）

## 目标

Grok Bot 的手动同步不再读取 `grokbot-usage.json`，改为与现有本机桌面连接器相同的辅助功能路径：按下 Grok Bot 左下角头像，从账户栏目读取套餐与已用百分比，悬浮圆环继续显示剩余百分比。

当前真实界面已确认栏目项形如 `Premium 96% 已用`，应保存为已用 96%、展示为剩余 4%。

## 方案边界

- 新增独立的 `GrokBotAX` 本机读取层，复用 `AXShared` 的受限遍历方式。
- 自动刷新保持原有行为，只报告安装／运行状态，不读取数值、不打开头像栏目。
- 用户点击主界面或悬浮窗的手动同步按钮时才允许打开栏目；按钮文案改为“读取本机额度”。
- 若栏目已经展开，直接读取，不重复点击；只有本次读取打开的栏目才在结束后用直投 Escape 收起。
- Grok Bot 正在前台使用时，不主动导航；未运行、未授权辅助功能、头像缺失、栏目未出现或额度格式变化时给出明确状态或错误，并保留上次成功读数。
- 不发起网络请求，不读取聊天、Cookie、凭证或 Grok Bot 私有数据库，不点击套餐、设置、退出登录等菜单项。

## 解析与数据流

1. 从窗口最下方、靠左且带标题的 `AXPopUpButton` 中定位头像，避免命中“分享”或“输入框操作”。
2. 只接受完整匹配 `<套餐> <0...100 数字>% 已用` 的栏目文本；支持整数和小数，拒绝剩余量、越界值、非有限值及多个互相冲突的候选。
3. 成功读取后以当前时间为 `capturedAt`，保存套餐、已用百分比和来源类型；`resetsAt` 为 `nil`，不沿用旧快照重置时间，也不声称栏目提供了共享范围。
4. `ManualReading` 以可选字段扩展，旧存档无需迁移且继续按历史快照口径展示。新记录明确标记为头像栏目来源。
5. 新记录的状态文案使用“额度剩余 X%（已用 Y%）”，包含套餐和采集时间，不写“本周剩余”或未提供的重置时间。圆环标签仅为剩余百分比，过期仍靠灰色、透明度和说明区分。
6. 成功读取替换旧读数；失败不制造 0% 或 100%，也不清除上次成功记录。

## 测试与交付

- 先增加失败回归：真实格式、带小数格式、错误语义、越界值、冲突候选、来源展示、按钮文案和自动刷新禁止读取。
- 保留既有 JSON 解析回归作为旧存档兼容验证，但生产手动同步不再调用文件提供者。
- 运行 Grok Bot 解析／展示回归、Agent 自动发现与悬浮窗可见性回归，并编译框架。
- 在真实 Grok Bot 上执行一次手动读取，确认 96% 已用对应 4% 剩余、旧“15.2%”被替换且栏目收起；不读取或复述聊天内容。
- 更新版本与 README，完整备份并核验账户、历史、设置、账本和钥匙串路径，构建签名安装后检查 Spotlight／LaunchServices 唯一入口，保留回滚与发行包，再推送源码和 GitHub Release。
