# Tokscale pricing and local scan network audit

Audit date: 2026-10-18. This is source evidence and isolated-fixture validation. It does **not** establish the reported sustained “4M/s” traffic's runtime cause, unit, direction or responsible PID.

## Pinned resource and observed source paths

The app executes its bundled `tokscale` directly. It has no runtime tool installer, automatic dependency download or “latest” tool resolution. `pin.json` still pins Tokscale 4.17.0, revision `37e347fedf8fee1059742e9fffa2deb8b4ad3bc9`, its release source, base binary, local patch and SHA-256. The resource binary and patch were rehashed during this audit and match `pin.json`:

The following files were read at that exact revision; these links are evidence for the pre-change behavior, not current-head guesses:

- [core `lib.rs`](https://github.com/Javis603/tokscale/blob/37e347fedf8fee1059742e9fffa2deb8b4ad3bc9/crates/tokscale-core/src/lib.rs#L5682): `get_model_report` (line 4541) and `generate_local_graph_report` (5341) use `load_pricing_for_local_parse` (5682). `TOKSCALE_PRICING_CACHE_ONLY=1` calls `load_cached_any_age` directly. Without it, the local report requests the pricing service and only falls back after failure. The bundled local-record patch calls the same loader.
- [pricing `mod.rs`](https://github.com/Javis603/tokscale/blob/37e347fedf8fee1059742e9fffa2deb8b4ad3bc9/crates/tokscale-core/src/pricing/mod.rs#L416): three sources fetch concurrently. The `OnceCell` is process-local; it cannot coalesce separate CLI launches. Failed sources degrade to their own stale cache.
- [pricing `cache.rs`](https://github.com/Javis603/tokscale/blob/37e347fedf8fee1059742e9fffa2deb8b4ad3bc9/crates/tokscale-core/src/pricing/cache.rs#L6): TTL is 3,600 seconds, future timestamps are rejected, writes use temp-file rename. With this app's `TOKSCALE_CONFIG_DIR`, all subprocesses share `cache/pricing-litellm.json`, `pricing-openrouter.json`, and `pricing-models-dev.json`; the legacy-directory fallback is disabled. A successfully populated valid disk cache therefore prevents repeated downloads by subsequent processes. No cross-process fetch lock, persistent failure backoff or conditional HTTP request appears in these pricing modules.
- [pricing `fetch.rs`](https://github.com/Javis603/tokscale/blob/37e347fedf8fee1059742e9fffa2deb8b4ad3bc9/crates/tokscale-core/src/pricing/fetch.rs): 30-second request timeout, 10-second connect timeout, at most 3 attempts for network/429/5xx, with 200/400 ms waits. This is a per-fetch retry policy, not a whole-history-scan budget.
- [LiteLLM](https://github.com/Javis603/tokscale/blob/37e347fedf8fee1059742e9fffa2deb8b4ad3bc9/crates/tokscale-core/src/pricing/litellm.rs#L599) and [models.dev](https://github.com/Javis603/tokscale/blob/37e347fedf8fee1059742e9fffa2deb8b4ad3bc9/crates/tokscale-core/src/pricing/models_dev.rs#L45): on a cache miss, download one public JSON each, parse/filter it, then write the normalized table. The upstream modules decode whole bodies without this app's streaming receive budget.
- [OpenRouter](https://github.com/Javis603/tokscale/blob/37e347fedf8fee1059742e9fffa2deb8b4ad3bc9/crates/tokscale-core/src/pricing/openrouter.rs#L282): `/api/v1/models`, followed by `/api/v1/models/{model-id}/endpoints` for recognized authors, with a semaphore of 10. A cache miss can therefore cause many requests, rather than a single table download.

Previously, one Swift scan launched `graph`, a report for every changed date (always including today/yesterday), and an all-history report. Every separate process could reach the price loader. Valid shared one-hour caches avoid repeated price downloads; missing, expired or unwritable caches and failed upstreams need separate runtime measurement. No claim is made here that a particular branch occurred on the user's machine.

## Enforced app policy

- Every historical `graph` and JSON report now receives `TOKSCALE_PRICING_CACHE_ONLY=1`. Cold and stale caches do not silently authorize a price request. Existing cached rates and custom prices remain usable; unknown cost stays `nil`, never an invented zero. Notices expose missing tables and table timestamps older than one hour. Existing ledger/history is not erased or replaced by a cache failure.
- Only the explicit `UsageEngine.refreshPublicPrices` method performs price networking. It requests two fixed HTTPS JSON endpoints (LiteLLM and models.dev), once each, through `BoundedHTTP` category `pricing`, with a 16 MiB streamed receive limit and 45-second deadline per source. It makes no OpenRouter request, endpoint fan-out or CLI pricing request. Previously stored OpenRouter tables remain readable.
- Responses must have HTTP 200, expected object/model/rate structure, finite nonnegative numeric rates and at least one usable row. models.dev's per-million units normalize to the engine's per-token cache format. A source failing HTTP or validation preserves its previous cache. A receipt records source URL, capture time, original download SHA-256, normalized cache SHA-256 and model count. The SHA-256 receipts provide local integrity evidence; they are not an independent publisher signature.
- A successful manual update has a one-hour persisted reuse window. Concurrent clicks and failed/partial/cancelled updates have a 15-minute persisted retry lease. There is no background price timer and no price refresh from `scan`.
- A per-configuration-directory file lock serializes subprocesses and custom-price/cache writes across tasks, windows and processes. Same-source repeat scans within 30 seconds reuse the persisted numeric snapshot without spawning a CLI. Later scans probe `graph` once and skip date/all-history reports if both graph and source content still agree. The snapshot retains its actual capture time and adds a reuse notice.
- Report reuse is deliberately limited to verified Codex, Claude and Kimi source roots, including Codex's two default Headless roots or its override, Kimi's narrower desktop-session subtree, selected-client scanner `extraScanPaths`, and settings/recovery inputs. The UI's discovery path list is not assumed to be an exhaustive scanner manifest. The presence of another selected tool's data, a dynamically configured database, or another client in the actual graph disables report reuse and runs the real scanner. Wide tool app-data folders containing files such as `auth.json` are not content-hashed for this optimization. With an expanded client selection, every scan still probes the graph; only a selection entirely within the verified clients may also suppress graph subprocesses inside 30 seconds.
- Source files use SHA-256; inode/size/mtime/ctime identity permits reuse of an existing content digest. New/changed content is streamed. An unreadable/mutating source, more than 50,000 filesystem items, 512 MiB of newly hashed bytes or 15 seconds per manifest pass disables reuse and lets the real scanner run. A changed session with unchanged day totals still invalidates report reuse. The disposable numeric snapshot contains only existing numeric DTOs, hashed source paths and digests; it is not a user-data migration or ledger replacement.
- A whole local scan, including lock wait and all reports, has a 180-second budget. `posix_spawn` creates a dedicated process group before exec. Cancellation, timeout and output overflow terminate that group and its helper descendants, escalating from TERM to KILL. No app-wide or system-wide process kill is used.

## Targeted verification

`Tests/UsageEnginePolicyRegression.swift` runs a synthetic CLI in an isolated home and intercepts both pricing URLs with `URLProtocol`. It verifies cold-cache cache-only environment, zero duplicate processes on unchanged repeat scans, same-total/different-session invalidation, Headless and scanner-extra-path invalidation, conservative unsupported-tool fallback, concurrent scan merging, cancellation of a TERM-resistant descendant, exactly two explicit pricing requests, rate units, receipts, one-hour reuse, finite failures/15-minute backoff, malformed-source preservation and pricing diagnostics. It does not contact real services or start the app/browser.

The existing `UsageEngineRegression.swift` runs the actual bundled binary with synthetic logs, an isolated home and fresh empty public-price caches. It continues to cover daily/session counts, cumulative/cache/reasoning buckets, unknown cost, custom/free pricing, workspace split aggregation, changed-day fingerprints and source-path privacy.

Runtime acceptance still requires matched-condition traffic observations for the already identified process tree and each authorized business scenario, including sustained idle. Passing these isolated tests does not prove a reduction in the user's real network traffic.
