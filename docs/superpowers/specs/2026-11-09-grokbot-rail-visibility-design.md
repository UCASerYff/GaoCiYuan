# Grok Bot 剩余额度与悬浮窗卸载过滤设计

日期：2026-11-09

## 目标

只修改搞词元，修正 Grok Bot 圆环的额度方向和陈旧标记，并让已卸载 Mac 应用对应的本地 Agent 圆环从悬浮窗隐藏。保留账户、历史、设置和钥匙串，不改其他独立应用。

## 额度语义

- 快照文件继续记录 `weeklyPercentUsed`，不改变现有 JSON 合同。
- 展示层计算 `weeklyPercentRemaining = 100 - weeklyPercentUsed`；输入已在 ingestion 限制为 0...100。
- Grok Bot 圆环的弧长、环下数字和主要详情文字均使用剩余百分比。例如已用 84.8% 时显示剩余 15.2%。
- 详情可注明原始已用百分比，避免换算口径不透明；不得把缺失或无效快照显示成 0% 或 100%。
- 环下数字不添加“旧”或“已用”前缀。过期快照通过灰色和降低透明度表达，帮助文字保留采集时间及非实时说明。

## 手动同步

- 保持现有点击悬浮窗圆环触发 `refresh(..., userInitiated: true)` 的行为。
- 只有用户主动点击圆环或详情按钮时读取 `grokbot-usage.json`；自动刷新只更新安装／运行状态，不打开额度文件。
- 不把读取本地最近一次快照描述成对 Grok Bot 的实时抓取。

## 卸载可见性

- 在悬浮窗账户清单入口统一应用可见性策略，渲染、几何尺寸、溢出计数和点击命中共用同一过滤结果。
- 有 Mac 应用身份的本地 Agent 以应用是否仍存在为悬浮窗可见条件；应用卸载后，即使 CLI 仍存在也隐藏。
- 纯 CLI 平台继续按 CLI／现有本机发现结果显示，API 账户不参与本机卸载过滤。
- 卸载过滤只影响悬浮窗，不删除或禁用账户，不改自动发现标记，不清空快照、历史、设置或凭据。重新安装后的发现扫描应恢复显示原账户。
- 复用现有工作区事件、应用激活和定期发现扫描；悬浮窗展开时请求一次重扫，缩短卸载后等待时间。扫描未完成或结果失效时不得把未知当成全部卸载。

## 代码边界

- `GrokBotUsageReport`：提供剩余额度换算和圆环展示模型，保持文件解析及快照合同不变。
- `MemberDiscovery`／`AgentPlatformTable`：区分 Mac 应用存在性与 CLI 存在性，向悬浮窗提供可测试的应用可见性依据。
- `FloatingPanel`：集中过滤可见账户并复用于 SwiftUI 与 AppKit 点击、几何逻辑；Grok Bot 使用剩余量圆环。
- 测试：覆盖已用到剩余的换算、边界值、过期标签无“旧”、自动刷新不读文件、应用卸载但 CLI 存在时隐藏、纯 CLI 与 API 不受影响、重新安装恢复、过滤后点击索引一致。
